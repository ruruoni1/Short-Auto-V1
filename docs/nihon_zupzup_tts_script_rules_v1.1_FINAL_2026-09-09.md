# 니혼줍줍 TTS 대본 제작 공통 지침 v1.1 FINAL

작성일: 2026-09-09  
적용 대상: 니혼줍줍 Long-form / Shorts의 TTS 내레이션 제작  
상태: 공통 운영 기준본

---

# 1. 문서 목적

이 문서는 니혼줍줍에서 TTS 음성을 만들기 위한 대본 작성 규칙을 정리한다.

영상 제작용 대본과 TTS 대본은 분리한다.

TTS 대본은 다음에 집중한다.

- 자연스러운 한국어 낭독
- 안정적인 발음
- 적절한 호흡
- 편집하기 쉬운 문장 단위
- 애니/일드 원작 대사와 자체 내레이션의 분리

---


# 1-A. 기본 TTS 엔진

니혼줍줍의 기본 TTS 합성 엔진은 **사용자 PC에 설치된 로컬 VOICEVOX**다.

이 문서는 “무엇을 읽게 할지”를 정의하고, 실제 VOICEVOX 연결/화자 선택/합성 방식은 `nihon_zupzup_voicevox_integration_rules_v1.0_FINAL_2026-09-09.md`를 따른다.

- 특정 VOICEVOX 화자를 문서에서 미리 고정하지 않는다.
- 프로그램이 로컬 Engine의 `/speakers` 목록을 가져와 화자와 스타일을 표시한다.
- 사용자가 직접 선택한 화자/스타일을 기본 보이스 프로필로 저장한다.
- 최종 대본 검수는 실제 선택 보이스로 미리듣기 후 확정한다.

---
# 2. 최상위 원칙

> **니혼줍줍 TTS 대본은 한글 표기만 사용한다.**

일본어 표현도 일본어 원문으로 쓰지 않고
TTS가 자연스럽게 읽을 수 있도록 한국어 독음으로 표기한다.

예:

- 俺 → 오레
- 僕 → 보쿠
- 私 → 와타시
- お前 → 오마에
- 貴様 → 키사마
- 役割語 → 야쿠와리고
- じゃ → 쟈

---

# 3. 일본어 원문 사용 금지

TTS 마스터 대본에는 일본어 한자, 히라가나, 가타카나를 기본적으로 넣지 않는다.

이유:

- 한국어 TTS에서 발음 오류 가능성
- 다국어 음성 전환으로 인한 억양 변화
- 문장 리듬 불안정
- 발음 일관성 저하

일본어 원문은:

> **화면 자막 / 그래픽 / 편집용 데이터**

에서만 사용한다.

---

# 4. 애니·일드 원작 대사 제외 원칙

TTS 대본에는 애니·일드 원작 장면의 실제 대사를 포함하지 않는다.

이유:

- 해당 장면은 원작 음성을 직접 사용하는 구간
- 자체 TTS 음성과 원작 대사를 명확히 분리하기 위함
- 편집 시 장면 삽입 위치를 관리하기 쉬움

기본 구조:

> TTS 내레이션  
> → 원작 장면  
> → TTS 내레이션

원작 대사가 끝난 뒤의 해설부터 TTS에 포함한다.

---

# 5. 제작용 대본과 TTS 대본 분리

## 제작용 대본

포함:

- 원작 대사
- 작품명
- 화수
- 타임코드
- 화면 자막
- 일본어 원문
- 편집 큐
- 그래픽 지시
- 프리즈/확대/전환
- TTS 내레이션

## TTS 대본

포함:

- 실제로 읽을 한국어 내레이션만

제외:

- 원작 대사
- 작품명/화수
- 타임코드
- 화면 지시
- 편집 지시
- 자막용 일본어 원문
- 괄호형 제작 메모

# 6. 일본어 독음 표기 원칙

일본어 표현은 시청자가 실제로 듣는 발음에 가까운 한국어 표기를 우선한다.

예:

- 大丈夫 → 다이죠부
- 本当 → 혼토
- ほんま → 혼마
- うまい → 우마이
- やばい → 야바이
- 俺 → 오레
- 僕 → 보쿠
- 私 → 와타시
- お前 → 오마에
- 貴様 → 키사마

기계적인 한글 치환보다 자연스러운 청취 발음을 우선한다.

---

# 7. 긴 일본어 대사는 TTS로 재현하지 않는다

애니/일드의 긴 실제 일본어 대사를
한국어 독음으로 전체 읽게 만들지 않는다.

예:

금지:
> 힌메루 나제 오마에와 오레니 이노치오 아즈케루난테 이에룬다...

권장:
> 방금 대사에는 오마에와 오레가 같이 들어 있었습니다.

즉 일본어 전체 대사는 원작 장면에서 듣고,
TTS는 핵심 표현만 다시 언급한다.

---

# 8. 표현 소개 방식

핵심 일본어 표현은 TTS에서 필요한 만큼만 한글 독음으로 읽는다.

권장:

> 키사마.

> 오레, 보쿠, 와타시.

> 오마에는 한국어로 ‘너’라고 번역할 수 있습니다.

피해야 할 것:

> 키사마, 한자로 귀할 귀에 모양 양...

처럼 화면 정보까지 전부 음성으로 읽는 구성.

화면으로 보여줄 수 있는 정보는
필요 이상으로 TTS에 넣지 않는다.

---

# 9. 한자 설명이 필요한 경우

한자의 의미가 콘텐츠 핵심일 경우에는
일본어 원문을 읽는 대신 한국어로 설명한다.

예:

> 키사마를 한자로 보면 조금 이상합니다.

> 앞 글자는 ‘귀하다’라는 뜻을 가지고 있고,
> 뒤의 ‘사마’는 상대를 높여 부를 때도 쓰는 표현입니다.

화면에서는 일본어 원문을 별도로 보여준다.

---

# 10. TTS 문장 길이

한 문장을 지나치게 길게 만들지 않는다.

권장:

> 10~25어절 전후

긴 설명은 두세 문장으로 나눈다.

예:

나쁜 예:
> 일본어에서는 어떤 1인칭을 선택하는지에 따라 말하는 사람의 성격과 상대와의 관계 그리고 당시 상황이나 사회적 위치까지 다양한 정보가 함께 전달될 수 있기 때문에...

권장:
> 일본어에서는 어떤 일인칭을 고르느냐에 따라 느낌이 달라질 수 있습니다.

> 화자의 말투와 관계, 상황, 인상까지 함께 느껴질 수 있습니다.

---

# 11. 호흡 설계

TTS는 문장 사이 호흡이 중요하다.

강조가 필요한 표현은 독립 문장으로 분리한다.

예:

> 키사마.

> 그런데 이 말, 조금 이상합니다.

또는:

> 중요한 건 뜻이 아닙니다.

> 관계입니다.

이 방식은 Remotion/HyperFrames에서
컷과 타이포 타이밍을 잡기도 쉽다.

---

# 12. 쉼표 사용 원칙

쉼표는 문법보다 음성 호흡을 우선한다.

단, TTS 엔진이 쉼표에서 지나치게 길게 쉬는 경우에는
쉼표를 줄인다.

최종 쉼표 사용은 실제 TTS 테스트 후 조정한다.

---

# 13. 문단 단위

한 문단에는 하나의 생각만 넣는다.

권장:

> 오마에는 한국어로 그냥 ‘너’라고 번역할 수 있습니다.

> 그런데 여기서 중요한 건 뜻보다 관계입니다.

> 누가 누구에게 말하느냐에 따라 느낌이 달라집니다.

문단 단위는 향후:

- 장면 분리
- 자막 분리
- 애니메이션 타이밍
- 컷 자동화

의 기준으로 활용할 수 있다.

---

# 14. 질문 문장 활용

Discovery 콘텐츠에서는 질문을 적극 활용한다.

예:

- 왜 그럴까요?
- 어떤 캐릭터가 떠오르세요?
- 그런데 현실에서 이렇게 말하면 어떨까요?
- 왜 이 캐릭터는 오레라고 했을까요?

질문 직후에는 너무 빨리 답하지 않는다.

짧은 호흡 또는 화면 전환을 넣을 수 있게 문단을 분리한다.

---

# 15. 강조 표현

강조할 단어나 문장은 단독 문장으로 만든다.

예:

> 뜻보다 관계입니다.

> 말투만 들어도 캐릭터가 보이는 거죠.

> 애니 일본어가 틀린 게 아닙니다.

강조를 위해 특수문자나 이모지를 넣지 않는다.

---

# 16. 괄호 사용

TTS 마스터 대본에서는 괄호 사용을 최소화한다.

피해야 할 것:

> 역할어, 야쿠와리고.

권장:

> 야쿠와리고.

> 한국어로는 역할어라고 합니다.

이유:

- 일부 TTS가 괄호를 부자연스럽게 처리
- 발음 흐름 방해
- 문장 분리가 더 편집 친화적

---

# 17. 숫자 표기

TTS에서 자연스럽게 읽어야 하는 숫자는
필요하면 한글로 변환한다.

예:

- 3가지 → 세 가지
- 50문장 → 쉰 문장

실제 TTS 엔진의 발음 결과를 우선한다.

---

# 18. 영어 표기

영어 철자를 TTS 대본에 직접 넣지 않는 것을 기본으로 한다.

예:

- MANSION → 맨션
- Content ID → 콘텐츠 아이디
- YouTube → 유튜브
- Shorts → 쇼츠
- Long-form → 롱폼

단, 브랜드나 고유명사의 공식 발음이 중요하면
한글 독음을 별도로 정한다.

---

# 19. 고유명사 표기

애니 캐릭터명, 작품명, 일본 인명은
한국에서 통용되는 한국어 표기를 우선한다.

예:

- 프리렌
- 슈타르크
- 힌멜

TTS 발음이 어색하면
실제 음성 결과에 맞춰 표기를 조정할 수 있다.

---

# 20. 원작 장면 연결 문장

원작 장면 직후 TTS가 시작될 때는
시청자가 방금 들은 대사를 자연스럽게 이어받게 한다.

권장:

> 방금 슈타르크는 자신을 오레라고 불렀습니다.

> 이번 문장에는 두 가지가 같이 들어 있었습니다.

> 방금 대사에서 쟈라는 말끝이 들렸습니다.

피해야 할 것:

> 앞에서 보신 장면을 분석해보겠습니다.

니혼줍줍은 강의보다 발견 톤을 유지한다.

---

# 21. 원작 장면 앞 연결 문장

원작 장면을 보여주기 전에는
대사를 미리 전부 설명하지 않는다.

권장:

> 이번에는 이 장면을 한번 들어보세요.

> 그런데 같은 단어가 여기서는 조금 다르게 들립니다.

> 또 하나만 들어보겠습니다.

이후 원작 클립 재생.

---

# 22. TTS 톤

기본 톤:

> **같이 재미있는 일본어를 발견하는 사람**

피해야 할 표현:

- 오늘 배워볼 표현은
- 이번 시간에는
- 외워보도록 하겠습니다
- 지금부터 설명하겠습니다
- 다음 항목은
- 첫 번째로

권장:

- 이 말, 많이 들어보셨죠?
- 그런데 조금 이상합니다.
- 한번 생각해볼까요?
- 여기서 재미있는 점이 하나 있습니다.
- 이제 공통점이 보이기 시작합니다.

# 23. 감정 과장 금지

TTS 내레이션은 지나치게 쇼호스트처럼 만들지 않는다.

피해야 할 것:

- 정말 충격적입니다!
- 믿기지 않으시죠?
- 엄청난 비밀이 있습니다!
- 반드시 알아야 합니다!

권장:

- 그런데 조금 재미있는 점이 있습니다.
- 여기서 느낌이 달라집니다.
- 이 부분이 꽤 흥미롭습니다.

# 24. TTS와 화면 역할 분리

TTS는 모든 정보를 읽지 않는다.

## TTS가 담당
- 이야기
- 질문
- 설명
- 연결
- 결론

## 화면이 담당
- 일본어 원문
- 한자
- 화살표
- 관계도
- 비교표
- 작품명
- 화수
- 타임코드
- 키워드 강조

핵심:

> **보이는 정보와 들리는 정보를 똑같이 만들지 않는다.**

# 25. Remotion / HyperFrames 연계 원칙

TTS 대본의 문단은 영상 씬 단위의 기본 후보가 된다.

예:

```text
문단 01
애니 좀 보셨다면 이 말, 정말 많이 들어보셨죠?

문단 02
키사마.

문단 03
그런데 일본에서 실제 사람한테 이렇게 말하면 어떨까요?
```

이후 음성 생성 후 타임코드를 확보하면:

```text
scene_01
start: 00:00.000
end: 00:02.900

scene_02
start: 00:02.900
end: 00:03.700
```

처럼 Remotion 또는 HyperFrames의 씬 타이밍으로 변환할 수 있다.

---

# 26. TTS 제작 후 검수

TTS 생성 후 반드시 실제 음성을 듣고 확인한다.

검수 항목:

- 일본어 독음이 자연스러운가?
- 고유명사가 정확하게 들리는가?
- 문장 끝 호흡이 어색하지 않은가?
- 쉼표에서 지나치게 오래 쉬지 않는가?
- 질문 억양이 자연스러운가?
- 단독 강조 문장이 너무 끊겨 보이지 않는가?
- 숫자 발음이 자연스러운가?
- 영어 단어 발음이 튀지 않는가?

---

# 27. 발음 문제 수정 원칙

TTS가 잘못 읽으면
맞춤법보다 실제 음성을 우선하여 표기를 조정할 수 있다.

엔진별 예외 표기는 실제 TTS 테스트 후
별도 발음 사전에 관리하는 것을 권장한다.

# 28. TTS 출력 파일 관리

권장 구조:

```text
production/
├─ final_script.md
├─ tts_script.md
├─ tts_audio.wav
```

## final_script.md

## timeline.json

# 30. 향후 Skill 전환 조건

현재는 MD 공통 지침으로 운영한다.

다음 조건이 충족되면
별도의 `tts-script-builder` Skill 제작을 검토한다.

- 실제 영상 2~3편 이상 제작
- 사용하는 TTS 엔진 확정
- 일본어 독음 오류 패턴 확인
- 적정 문장 길이 확인
- 쉼표/마침표 처리 방식 확인
- Remotion/HyperFrames 제작 흐름 확정

Skill의 예상 역할:

> 최종 영상 대본 입력  
> → 원작 대사 제거  
> → 편집 지시 제거  
> → 일본어 원문을 한국어 독음으로 변환  
> → TTS 호흡에 맞게 문장 분리  
> → TTS 마스터 대본 출력

# 31. 최종 체크리스트

- [ ] TTS 대본이 한글로만 작성됐는가?
- [ ] 일본어 원문이 남아 있지 않은가?
- [ ] 일본어 표현은 한국어 독음인가?
- [ ] 원작 애니/일드 대사를 제거했는가?
- [ ] 편집 지시가 제거됐는가?
- [ ] 화면 자막 지시가 제거됐는가?
- [ ] 긴 문장이 적절히 분리됐는가?
- [ ] 강조 문장이 독립되어 있는가?
- [ ] 괄호 사용을 최소화했는가?
- [ ] 고유명사 발음을 확인했는가?
- [ ] 숫자와 영어 표현이 자연스럽게 읽히는가?
- [ ] 원작 장면 전후 연결이 자연스러운가?
- [ ] 실제 TTS 음성을 청취 검수했는가?
