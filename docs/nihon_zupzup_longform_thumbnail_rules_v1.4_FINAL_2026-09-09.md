# 1. 문서 목적

이 문서는 니혼줍줍 Long-form 영상의 썸네일 제작 기준을 최종 정리한 운영 문서다.

기존 v1.0 → v1.1 → v1.2 과정에서 정리한 규칙과,
실제 썸네일 반복 테스트에서 확인된 실패/개선 패턴을 모두 반영한다.

최종적으로 니혼줍줍 Long-form 썸네일은 다음 두 가지 기본 유형으로 운영한다.

1. **Discovery Long-form**
2. **Training Long-form**

비교형, 반전형, 문제형, 오해형은 별도 템플릿이 아니라 Discovery의 파생형으로 사용한다.

---

# 2. 최종 운영 구조

## TYPE A — Discovery Long-form

역할:
- 신규 시청자 유입
- 호기심 유발
- 클릭
- 조회수
- 브랜드 인식
- 언어/문화 차이에 대한 관심 확대

핵심 메시지:
> 문제 / 반전 / 차이 / 오해 / 궁금증

대표 문구 예:
- 만숀이 아파트라고?
- 우마이, 써도 돼?
- 혼마가 진짜라고?
- 현실에선 안 씁니다
- 일본에서는 뜻이 다릅니다

---

## TYPE B — Training Long-form

역할:
- 반복 학습
- 듣기 훈련
- 말하기 훈련
- 재방문
- 긴 시청시간 자산
- 실전 표현 축적

핵심 메시지:
> 무엇을 / 얼마나 / 어떤 방식으로 학습하는가

대표 문구 예:
- 여행 일본어 50문장
- 식당 회화 30분
- 매일 듣는 일본어 100문장
- 입이 트이는 회화 훈련

---

# 3. 최상위 원칙

> **한 썸네일 = 한 아이디어**

모든 롱폼 썸네일은 다음을 따른다.

- 브랜드보다 클릭 메시지가 우선한다.
- 영상 전체 내용을 설명하지 않는다.
- 가장 강한 사례 하나만 대표로 사용한다.
- 제목과 썸네일은 같은 말을 그대로 반복하지 않는다.
- 모바일에서 1초 안에 이해되어야 한다.
- 일본어를 읽지 못해도 핵심을 이해할 수 있어야 한다.
- 클릭 이후 실제 영상 내용과 약속이 일치해야 한다.
- 자체 데이터가 쌓이면 외부 연구보다 니혼줍줍 자체 데이터를 우선한다.

---

# 4. 언어 표기 최종 원칙

니혼줍줍의 주요 타깃에는 일본어 초보자와 일본어를 읽지 못하는 시청자가 포함된다.

따라서:

> **일본어 원문만으로 핵심 훅을 만들지 않는다.**

기본 구조:

> **한국어 = 클릭 메시지**  
> **한국어 독음 = 일본어를 읽지 못하는 시청자를 위한 연결 장치**  
> **일본어 원문 = 소재 / 증거 / 학습 요소**

핵심 훅은 다음 중 하나만으로도 이해되어야 한다.

- 한국어
- 한국어 독음
- 한국어 + 한국어 독음

---

# 5. 언어 표기 우선순위

## 1순위 — 한국어 훅

예:
- 아파트라고?
- 진짜 이런 뜻?
- 실제로 안 씁니다
- 일본에서만 통합니다

## 2순위 — 한국어 독음

예:
- 만숀
- 혼마
- 우마이
- 야바이
- 콘센토

## 3순위 — 일본어 원문

예:
- マンション
- ほんま
- うまい
- やばい
- コンセント

일본어 원문은 보여줄 수 있지만,
일본어를 몰라도 전체 메시지가 이해되어야 한다.

---

# 6. Discovery Long-form 최종 공식

> **강한 시각 요소 1개 + 한국어/독음 핵심 훅 1개 + 필요 시 일본어 보조표기 1개**

### 핵심
- 질문
- 반전
- 오해
- 비교
- 의미 차이

### 텍스트
기본 시작점:
> **2~5단어**

단어 수 자체보다 하나의 메시지가 중요하다.

# 7. Discovery 대표 훅 유형

## 반전형
- 일본에서만 통합니다
- 뜻이 완전히 다릅니다
- 애니에서만 자연스럽다

## 문제형
- 왜 이렇게 말하지?
- 왜 회화가 안 늘까?

## 비교형
- 혼토 vs 혼마
- 오이시 vs 우마이

## 오해형
- 실제로 쓰면 이상합니다
- 이 뜻이 아닙니다
- 일본에서는 다르게 씁니다

# 8. Discovery에서 피해야 할 문구

다음은 카테고리 설명에 가까워 클릭 이유가 약하므로 기본적으로 사용하지 않는다.

- 일본어 공부
- 일본어 표현 배우기
- 오늘의 일본어
- 기초 일본어
- 와세이에이고 알아보기
- 일본어 회화 강의

# 9. Discovery 시각 요소 규칙

기본:

> **주인공 1개**

가능한 주인공:
- 얼굴
- 건물
- 음식
- 표지판
- 특정 물건
- 일본어 표현
- 비교 대상
- 상징적 상황

피해야 할 것:
- 오브젝트 여러 개 나열
- 표현 여러 개 나열
- 얼굴 + 아이콘 + 화살표 + 카드 다수
- 영상 목차를 한 썸네일에 표현
- 여러 메시지를 동시에 강조

---

# 10. 얼굴 사용 규칙

얼굴은 적극 검토하되 필수는 아니다.

vidIQ 연구 참고:
- 아웃라이어 전체 얼굴 사용 약 69%
- 상위 100개 약 75%
- 상위 50개 약 80%
- 과장된 놀람 표정 약 5%

얼굴 사용 시:
- 화면 약 1/4~1/3
- 모바일에서도 명확할 것
- 자연스러운 감정
- 콘텐츠와 표정이 일치할 것

권장 감정:
- 궁금함
- 당황
- 확신
- 고민
- 재미

피해야 할 것:
- 억지 놀람 표정
- 입 크게 벌린 전형적 클릭베이트 표정
- 콘텐츠와 무관한 과장 감정

---

# 11. 얼굴 없이 오브젝트형으로 가는 경우

다음 주제는 얼굴보다 오브젝트나 표현 자체가 더 강할 수 있다.

# 13. Discovery 테스트 과정에서 확인된 실패 패턴

## 실패 1 — 메시지 과다

한 썸네일에:
- 일본에서만 통합니다
- 맨션이 아파트라고?
- MANSION ≠ マンション
- 영어 뜻
- 일본어 뜻
- 채널명

등 여러 정보를 동시에 넣는 방식.

판정:
> 실패

---

## 실패 2 — 과장된 유튜브 스타일

- 지나치게 큰 외곽선
- 깊은 3D 그림자
- 붓터치
- 빨강/노랑 강조 과다
- 큰 놀람 표정

판정:
> 니혼줍줍의 발견형 톤과 맞지 않음

---

## 실패 3 — 일본어 원문이 메인

`マンション`을 크게 보여주고
`아파트라고?`를 보조로 배치.

문제:
일본어를 읽지 못하는 사람은 핵심 단어를 해독할 수 없음.

개선:
> **만숀이 아파트라고?**

---

## 실패 4 — 비교 대상이 언어가 아니라 건물처럼 보임

서양 대저택과 일본 아파트를 반반 배치했으나
언어 차이보다 부동산 비교처럼 보임.

개선:
- 언어 차이를 명확히 하거나
- 강한 사례 하나만 보여준다.

---

# 14. Discovery 스타일 세부 규칙

## 텍스트 크기
- 모바일 가독성은 확보
- 화면을 꽉 채우지 않음
- 주인공과 충돌하지 않음
- 충분한 여백 확보

## 외곽선 / 그림자
- 두꺼운 검은 외곽선 최소화
- 3D 그림자 최소화
- 그림자는 가독성 보조 수준

## 색상
핵심 단어 하나 정도만 포인트 컬러 사용 가능.

예:
- 만숀이 → 노랑
- 아파트라고? → 흰색

한 단어 내부에서 조사만 다른 색으로 나누지 않는다.

## 일본어 보조표기
- 박스 없음
- 붓터치 없음
- 아이콘 없음
- 일반 텍스트로 작게

---

# 15. Training Long-form 최종 공식

> **학습 상황 + 숫자/범위 + 학습 방식 또는 결과**

Discovery와 달리 Training은 미스터리보다 정보 전달을 우선한다.

핵심 질문:
> 이 영상을 보면 무엇을 얼마나 훈련할 수 있는가?

---

# 16. Training 숫자 사용 규칙

Training에서는 숫자를 적극적으로 활용한다.

예:
- 30분
- 50문장
- 100표현
- 1시간
- 20상황
- 10회 반복

숫자는 장식이 아니라:

> **학습 범위와 약속**

을 나타낸다.

파일:
> `일본_여행_필수_회화_50문장.png`

메인:
> **여행 일본어**  
> **50문장**

보조:
> 반복듣기

시각 요소:
> 일본 여행자 1명 + 일본 여행 상황

구성:
- 왼쪽: 학습 정보
- 오른쪽: 여행자 1명
- 숫자 `50문장`을 강하게 강조
- 보조 문구 `반복듣기`는 작게
- 말풍선 없음
- 일본어 카드 없음
- 과도한 장식 없음
- 로고 없음

이 샘플을 Training Long-form 기본 디자인 기준으로 사용한다.

---

# 18. Training 샘플에서 확인된 좋은 점

- 학습 상황이 즉시 이해됨
- `50문장`으로 범위가 명확함
- `반복듣기`로 학습 방식이 보임
- 여행자 1명으로 시각 요소가 정리됨
- 일본어 원문을 과도하게 사용하지 않음
- 모바일 가독성이 좋음
- 정보와 이미지의 역할 분리가 명확함

---

# 19. Training에서 피해야 할 실패 패턴

피해야 할 예:
- 일본 여행 필수
- 일본어 회화
- 50문장
- 반복듣기
- 일본어 말풍선
- 일본어 보조문장
- 추가 설명

를 모두 동시에 넣는 방식.

문제:
> Training이라도 한 썸네일에 정보가 너무 많으면 핵심 학습 약속이 흐려진다.

권장:
> **여행 일본어 / 50문장 / 반복듣기**

정도로 계층을 단순화한다.

# 20. Discovery와 Training 차이

| 항목 | Discovery Long | Training Long |
|---|---|---|
| 목적 | 호기심/클릭 | 학습 가치 전달 |
| 메시지 | 문제·반전·차이 | 범위·숫자·결과 |
| 텍스트 | 2~5단어 중심 | 정보형 가능 |
| 한국어 독음 | 적극 활용 | 필요 시 |
| 일본어 원문 | 보조 | 최소/필요 시 |
| 얼굴 | 적극 검토 | 필요 시 |
| 오브젝트 | 강한 사례 1개 | 학습 상황 대표 이미지 |
| 제목 중복 | 최소화 | 일부 허용 |
| 미스터리 | 높음 | 낮음 |
| 정보성 | 중간 | 높음 |

# 21. 비교형은 별도 템플릿을 만들지 않는다

예:
- 혼토 vs 혼마
- 오이시 vs 우마이
- MANSION ≠ 만숀

비교형은 모두 Discovery의 파생형으로 사용한다.

초기 운영에서는:

> **Discovery 기본 템플릿 1개 + Training 기본 템플릿 1개**

만 유지한다.

이유:
- 브랜드 분산 방지
- 초기 데이터 비교 용이
- 어떤 메시지가 강한지 판단하기 쉬움

# 23. 로고 사용

기본 원칙:

> **썸네일에 니혼줍줍 로고를 넣지 않는다.**

브랜드는 다음 요소로 구축한다.

- 폰트
- 여백
- 문구 구조
- 일본어 표기 방식
- 색상 감각
- 전체 디자인 언어

---

# 24. 모바일 우선 검수

모든 썸네일은 실제 YouTube 모바일 크기로 축소해 확인한다.

검수 질문:

1. 1초 안에 무엇이 핵심인지 보이는가?
2. 일본어를 읽지 못해도 이해되는가?
3. 핵심 오브젝트가 명확한가?
4. 글자가 화면을 과도하게 덮고 있지 않은가?
5. 경쟁 썸네일 사이에서도 구분되는가?
6. 클릭 이후 실제 영상과 약속이 일치하는가?

# 25. A/B 테스트 원칙

> **기본안이 완성된 후에만 A/B 테스트한다.**

색상만 바꾸는 테스트는 지양한다.

테스트해야 할 것:
> **클릭 가설**

Discovery 예:
- A — 구체 사례형: 만숀이 아파트라고?
- B — 반전형: 일본에서만 통합니다
- C — 비교형: MANSION ≠ 만숀

Training 예:
- A — 범위 강조형: 여행 일본어 50문장
- B — 결과 강조형: 여행 회화 이걸로 끝
- C — 상황 강조형: 일본 여행에서 꼭 듣는 50문장

단, 초기에는 기본 디자인을 유지하고 메시지 가설만 비교한다.

# 32. v1.4 제작 아키텍처 — 이미지와 텍스트 분리

니혼줍줍 롱폼 썸네일은 더 이상 AI 이미지 생성 단계에서 문구까지 렌더링하지 않는다.

최종 제작 구조:

> **텍스트 없는 베이스 이미지 → 편집 가능한 텍스트 레이어 → 최종 합성본**

## 베이스 이미지
- AI 생성 이미지 또는 정당하게 확보한 이미지/프레임
- 이미지 안에 한글/일본어/숫자/로고/타이포그래피를 생성하지 않는다.
- 이후 텍스트가 들어갈 여백과 시선 방향을 고려한다.
- 생성 프롬프트에는 `no text / no letters / no typography / no logo` 성격의 조건을 기본 포함한다.

## 텍스트 레이어
- 메인 훅, 보조 일본어, 숫자 등은 모두 별도 레이어로 관리한다.
- 위치, 크기, 폰트, 굵기, 색상, 외곽선, 그림자, 정렬, 자간, 행간을 재편집할 수 있어야 한다.
- A/B 테스트에서는 동일 베이스 이미지에 문구만 바꾼 파생본도 만들 수 있다.

## 프로젝트 저장
권장 구조:

```text
thumbnail_project/
├─ base_image.png
├─ thumbnail_project.json
└─ final_thumbnail.jpg
```

최종 JPG/PNG만 저장하지 않고 레이어 정보가 포함된 프로젝트 파일을 보존한다.

# 33. 애니·일드 콘텐츠의 원작 이미지 사용 원칙

특정 애니/일드 작품 또는 캐릭터의 인지도가 클릭 훅인 콘텐츠는 **해당 작품의 실제 장면 이미지를 우선 검토**한다.

## 우선 사용
- 특정 캐릭터 말투 분석
- 특정 작품의 대사 분석
- 특정 장면을 질문의 출발점으로 삼는 콘텐츠
- 작품/캐릭터 인지도가 썸네일 이해에 직접 도움 되는 콘텐츠

## 굳이 사용하지 않아도 되는 경우
- `오레/보쿠/와타시`처럼 여러 작품을 가로지르는 언어 개념
- 와세이에이고, 생활 표현 등 작품 자체가 핵심이 아닌 주제
- 특정 작품 이미지를 쓰면 영상 범위를 오해시킬 수 있는 비교형 콘텐츠

## 이미지 소스 우선순위
1. 내부 `공식 YouTube 클립 라이브러리`의 공식 영상에서 검토한 장면 프레임
2. 작품/제작사/방송사 공식 YouTube의 하이라이트·Shorts·切り抜き 프레임
3. 자체 제작/재현 이미지
4. AI 보조 이미지

공식 YouTube 영상이라는 이유만으로 자유 이용 이미지가 되는 것은 아니다. 실제 사용 여부는 별도 저작권 검토 대상이며, 단순 포스터 재게시보다 영상의 분석 대상이 되는 장면을 제한적으로 사용하는 방향을 우선한다.

# 34. 폰트 정책

프로그램 기본 폰트는 **상업적 사용과 앱 포함/재배포 조건이 명확한 오픈 라이선스 폰트**만 허용한다.

초기 허용 후보:
- Pretendard — SIL Open Font License
- Noto Sans KR / Noto Sans JP — Google Fonts 배포 라이선스 확인 후 고정 버전 등록
- Noto Serif KR / Noto Serif JP — Google Fonts 배포 라이선스 확인 후 고정 버전 등록
- IBM Plex Sans KR / IBM Plex Sans JP — SIL Open Font License

구현 규칙:
- 폰트마다 `name`, `version`, `source_url`, `license_id`, `license_text_path`를 등록한다.
- 앱과 함께 폰트를 배포할 경우 해당 라이선스/저작권 고지를 배포본에 포함한다.
- 출처나 라이선스가 불명확한 무료 폰트는 기본 목록에 넣지 않는다.
- 사용자가 외부 폰트를 직접 추가하는 기능은 가능하나 기본 제공 폰트와 구분하고 라이선스 확인 책임 안내를 표시한다.
